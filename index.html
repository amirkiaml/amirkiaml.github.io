Agentic SMS sales outreach for VoiceCaptures, built on the OpenAI Agents SDK and Twilio. Sends bulk cold outreach via a deterministic multi-agent drafting/picker pipeline, then hands live conversations to a stateful conversational SDR agent that responds to inbound replies in real time.

Walkthrough

Result: 44% of scraped business numbers can't receive SMS

37 leads scraped from Google Maps, 18 messaged, 8 delivered. Roughly half are office landlines — invisible across three days of development because every test went to my own mobile. Cost per delivered message is $0.020, not $0.009. Twilio's Lookup answers this directly but needs NPAC approval for Canadian numbers, so line type is recovered for free from delivery error codes instead, and send_sms refuses known landlines from then on.

Design note: rules that must always hold live in code

Five times a rule had to move out of a prompt: the CASL opt-out footer, GSM-7 punctuation, sub-4.0 ratings the hook agent would build insulting angles from. An instruction followed 98% of the time isn't a guarantee — and twice, tightening the instruction caused the next failure. 105 tests, 20 of them asserting the paths where a bug is a legal problem: a suppressed number can never be sent to, opt-outs survive prospect deletion, a blocked message never returns silence.

Design note: the autopilot agent has no tools

Output guardrails run after tool calls, so an agent holding send_sms can deliver an ungrounded message before any check sees it — and a text can't be unsent. It returns structured output; code decides. Replies are grounded in a YAML knowledge base with lexical rather than vector retrieval, because an off-topic question must retrieve nothing, and similarity search always returns a nearest neighbour.

Smaller builds & experiments

Agentic Task Runner

A FastAPI app where an agent parses a plain-language task, selects and executes tools in sequence, and returns a numbered execution trace with persistent history. Built to test native tool-calling against a hand-rolled planner.

FastAPI OpenAI Agents SDK tool_choice=required
Repository →

Key design decision

Started with a custom planner/executor design, but switched to native @function_tool + tool_choice="required" — each tool call happens with real prior results already in context, since the SDK's own conversation loop handles that automatically. Added DirectAnswerTool as an explicit "no tool applies" option to stop the model misusing the nearest tool on trivial inputs.

Tools implemented

Text processing, calculator, unit conversion, a mock weather lookup, and an explicit direct-answer fallback — deliberately trivial, so the routing behaviour is the thing under test.

A one-day hackathon hosted by BrainStation for Google, July 2023. Our team tackled growing public mistrust of AI: no transparency, privacy concerns, no way to verify how AI-driven results are produced.

DeepAnalytic — Retrieval over a Philosophy Corpus

A retrieval stack benchmarked across four architectures — naive, reranked, multi-query, and a custom critique-and-rerank agentic pipeline — over a scraped corpus of academic philosophy spanning roughly 800k pages.

Naive / Rerank / Multiquery / Agentic RAG Sentence Transformers (fine-tuned) Pipeline Benchmarking NLI Dataset Construction Web Scraping
View repository →

Project overview

DeepAnalytic applies LLMs and retrieval to analytic philosophy across thousands of papers and books. The domain is a hard case for retrieval on purpose: philosophical vocabulary is densely polysemous, so nearest-neighbour similarity routinely returns passages that use the same term in an unrelated sense. That failure mode is what the benchmarking is aimed at.

Retrieval architectures benchmarked

  • Naive RAG (chunk-400, text-embedding-3-small, cosine similarity)
  • RAG + reranking
  • Multi-query generation RAG
  • Custom multi-query → critique → rerank → generate pipeline (agentic RAG)
  • Systematic pipeline & parameter benchmarking across the above
  • Sentence-transformer fine-tuning for domain-specific vectorization
  • Natural Language Inference (NLI) dataset construction

Data & scope

Metadata for 28 Springer Nature philosophy journals (~800k pages), the entire Stanford Encyclopedia of Philosophy (2024 edition), and 10k+ pages from Analysis and other publishers, scraped and preprocessed for research use.

Most books teaching the mathematics under data science run ~350 pages, cost a lot, lean heavily on code, and teach surprisingly little actual math. This one is built to fix that: short, sharp, and math-first.

Part I covers the core mathematics — linear algebra, calculus, statistics, and probability theory. Part II builds on it to cover the mathematics underneath regression, tree methods, support vector machines, clustering, PCA, and neural networks, with Python implementations throughout.

Structured Propositions & Logics of Ground

Peer-reviewed paper in Synthese providing a unified semantics for propositional logics of impure ground using structured propositions.

Read paper →

Abstract

I show that the assumption of highly structured propositions can be leveraged to provide a unified semantics for various propositional logics of impure ground in a very expressive and flexible way. It is shown, in particular, that the induced models are capable of capturing an infinitude of grounding facts that follow from unrestricted logics of ground, but, due to certain artificial restrictions, are left unaccounted for by the existing semantics in the literature. It is also shown that our models, unlike the ones in the literature, are easily extendable to capture certain distinct views about iterated as well as identity grounding.

Practical Statistics for Data Practitioners

Open-source guide to descriptive and inferential statistics for real-world analytics, paired with reproducible Python code.

An open-source, hands-on guide to the descriptive and inferential statistics needed in real analytics and ML pipelines. Each concept is paired with clear intuition, minimal proofs, and fully reproducible Python code.
